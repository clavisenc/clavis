Turn off device encryption in Windows 11 (save the key first)

Many Windows 11 PCs encrypt their own drive during setup, without asking. That's device encryption, and it's why some people meet a BitLocker recovery screen they never knew they'd set up. You can turn it off, but usually you shouldn't, and either way the first step is the same: find your recovery key. Here's why your PC encrypted itself, how to decide, the Settings and command-line steps to turn it off, and what to do before a BIOS update instead.

Short answer: device encryption is BitLocker that Windows turns on by itself on supported PCs. First, save a copy of your recovery key from aka.ms/myrecoverykey. Then sign in as an administrator and set Settings → Privacy & security → Device encryption to Off; Windows decrypts the drive in the background. Microsoft recommends keeping it on; for a BIOS update, suspend it instead.

Why your PC encrypted itself

Microsoft describes device encryption as “a Windows feature that provides a simple way for some devices to enable BitLocker encryption automatically”, for the Windows drive and other fixed (internal) drives. It doesn't touch USB or external drives. On a PC that meets the requirements, it starts on its own once Windows setup has finished: “Unlike a standard BitLocker implementation, device encryption is enabled automatically so that the device is always protected.”

It happens in two stages:

  1. After setup, Windows encrypts the drives with a “clear key”. The key is stored on the drive unprotected, which Microsoft calls “the equivalent of standard BitLocker suspended state”. File Explorer shows a yellow warning icon on the drive while it's in this state.
  2. Protection switches on once the recovery key is backed up. On a personal PC, that's when an administrator signs in with a Microsoft account: Windows uploads the recovery key to that account, creates the TPM protector and removes the clear key. On a work or school PC, it's when the organization backs up the key to Microsoft Entra ID or Active Directory, if its BitLocker policy is set to do that. Microsoft's guidance for PC makers says protection is “enabled (armed) only after users sign in with a Microsoft Account” or a work account, and “until that, protection is suspended and data is not protected”.

The local-account trap. Microsoft's support page says that with a local account, device encryption “isn't turned on automatically”. Its technical overview adds that a PC that uses only local accounts “remains unprotected even though the data is encrypted”. So the drive can be encrypted while its key sits unprotected on it: encrypted, but not yet protecting you.

Why more PCs do this now. Device encryption still needs a TPM and Secure Boot. But “starting in Windows 11, version 24H2, the prerequisites of DMA and HSTI/Modern Standby are removed”, so many more PCs qualify. And if a PC didn't qualify at first, a later change such as turning on Secure Boot makes Windows switch it on “as soon as it detects it”.

Is Windows 11 encrypted by default, then? On PCs that meet the requirements, yes. Microsoft's Recall documentation says “Device Encryption or BitLocker are enabled by default on Windows 11”. It only protects you once the recovery key has been backed up to a Microsoft account or the organization's directory.

Is it on? A quick check

  • Open Settings → Privacy & security → Device encryption. Microsoft's support page also gives a shortcut, ms-settings:deviceencryption, which opens the page directly: press Windows key + R, type it and select OK. This also works on Windows 10.
  • Settings shows device encryption as on only once encryption is complete, so a PC that's still encrypting can look as if it's off.
  • A yellow warning icon on the drive in File Explorer means it's encrypted but the key isn't protected yet.

For the command-line check (manage-bde -status) and what each status means, see how to check if your drive is encrypted in Windows 11. If there's no Device encryption page at all, see device encryption not available in Windows 11. For how it compares with full BitLocker in Windows 11 Pro, see device encryption vs BitLocker on Windows 11 Home.

Do this first: save your recovery key

Look up the key now, while everything works. On another device, open aka.ms/myrecoverykey, sign in with the Microsoft account used on this PC, and find the key whose Key ID matches this PC's. To see this PC's ID, right-click Start (or press Windows key + X) and choose Terminal (Admin). On some PCs it's called Windows Terminal (Admin) or Windows PowerShell (Admin). Select Yes when Windows asks whether to allow changes. Then run manage-bde -protectors -get C: -Type RecoveryPassword and compare the ID listed under Numerical Password. If someone else set up the PC, the key may be in their Microsoft account. Write it down or print it, and keep that copy away from the laptop.

If no key in the account matches, get a copy before you go any further, while Windows still starts. In the same Terminal (Admin) window, this PowerShell command, based on one in Microsoft's BitLocker operations guide, shows the ID and the 48-digit recovery password: (Get-BitLockerVolume -MountPoint C).KeyProtector | Where-Object {$_.KeyProtectorType -eq 'RecoveryPassword'} | Format-Table KeyProtectorId,RecoveryPassword. Microsoft Support “doesn't have the ability to retrieve, provide, or recreate a lost BitLocker recovery key”, and without the key the fallback is a reset, which “will remove all of your files”.

On Windows Home, Microsoft doesn't say whether manage-bde and the BitLocker PowerShell commands work (we've only tested them there without administrator rights, when they refused). If they give an error on Home, the key listed at aka.ms/myrecoverykey is the copy to save. If no key there matches this PC, don't turn anything off until you have one.

Full steps, including work and school accounts: how to find your BitLocker recovery key in Windows 11.

Should you turn off device encryption?

Microsoft's position is clear: “It's recommended to keep device encryption on for any systems that support it.” Its BitLocker guide also says decryption should happen “when protection is no longer required, and not as a troubleshooting step”. Here's how that works out for the usual reasons people turn it off:

About performance. Microsoft says: “Historically, we have strived to keep BitLocker performance overhead within single digit percentage points.” It also says that on fast NVMe drives the impact is “more pronounced”, “especially on high-throughput and I/O intensive workloads like gaming or video editing”. Its answer is hardware-accelerated BitLocker, which arrived with the September 2025 update for Windows 11 24H2 and with 25H2 on supported PCs. Microsoft's December 2025 announcement named Intel vPro PCs with Intel Core Ultra Series 3 processors as the first, with other vendors to follow. Microsoft reports an average 70% saving in CPU cycles compared with software BitLocker. To see if your PC uses it, run manage-bde -status as administrator and look for Hardware accelerated under Encryption Method. If you still decide speed matters more, weigh it against what someone could read from the drive if the PC went missing.

How to turn off device encryption

Before you start: save your recovery key (above), sign in with an administrator account, and plug the laptop in. Back up anything you can't replace, as before any long disk operation. Microsoft gives no figure for how long decryption takes; it depends on the drive. If your PC has the Device encryption page in Settings, use it: it's the way Microsoft documents for turning device encryption off.

In Settings (recommended)

  1. Sign in to Windows with an administrator account. With a standard account, Microsoft says the Device encryption page may not appear.
  2. Open Settings → Privacy & security → Device encryption, or use the shortcut ms-settings:deviceencryption.
  3. Set Device encryption to Off (confirm if Windows asks). Microsoft's BitLocker overview says this Settings switch “can be used to turn device encryption on or off”.
  4. Windows starts decrypting the drive in the background. Leave the PC plugged in until it's done.
  5. To watch progress, run manage-bde -status in Terminal (Admin) (see the command-line steps below). Percentage Encrypted counts down as the drive is decrypted. Check every drive it lists, including any second internal drive.

From the command line (cmd or PowerShell)

On Windows Home, Settings is the documented way. As noted above, Microsoft doesn't say whether these commands work there; if one gives an error, use Settings instead.

  1. Right-click Start (or press Windows key + X) and choose Terminal (Admin). On some PCs it's called Windows Terminal (Admin) or Windows PowerShell (Admin). Select Yes when Windows asks whether to allow changes.
  2. Run manage-bde -status to see which drives are encrypted and their letters.
  3. Run manage-bde -off C:. Microsoft: it “decrypts the drive and turns off BitLocker. All key protectors are removed when decryption is complete.” It starts without asking you to confirm, so check the drive letter first.
  4. Repeat for any other internal drive that's encrypted, for example manage-bde -off D:.
  5. Run manage-bde -status again to follow progress. manage-bde -pause C: pauses decryption and manage-bde -resume C: carries on.

In the same window, the PowerShell command Disable-BitLocker -MountPoint C does the same.

On Windows 11 Pro, Enterprise or Education

Device encryption is the same BitLocker, so you can also search Start for BitLocker, open Manage BitLocker and choose Turn off BitLocker next to the drive, then confirm. Microsoft says BitLocker Drive Encryption “isn't available on Windows Home edition”, and that if Manage BitLocker isn't listed, you don't have the right edition; on Home, use Settings. More on the difference: device encryption vs BitLocker.

Afterwards

Microsoft says that if device encryption is turned off in Settings, “it will no longer automatically enable itself in the future. The user must enable it manually in Settings.” It doesn't say the same about manage-bde, PowerShell or Manage BitLocker. If you used one of those, open Settings → Privacy & security → Device encryption once decryption has finished (if your PC has that page) and check that it shows Off, and run manage-bde -status again after the next Windows feature update. If you change your mind, turn it back On on the same Settings page.

Suspend instead: before a BIOS or firmware update

A BIOS or UEFI firmware upgrade is one of the events Microsoft lists as causing the recovery screen at startup. Decrypting the whole drive to avoid that is overkill. Microsoft: “For planned scenarios, such as a known hardware or firmware upgrades, initiating recovery can be avoided by temporarily suspending BitLocker protection. Suspending BitLocker leaves the drive fully encrypted.” The order Microsoft gives PC makers is: suspend, apply the update, restart, resume.

  1. Save your recovery key first, in case anything goes wrong.
  2. Open Terminal (Admin) as in the command-line steps above and run Suspend-BitLocker -MountPoint "C:" -RebootCount 2, or manage-bde -protectors -disable C: -rc 2, which does the same. Protection then comes back by itself after two restarts. Firmware updates can restart the PC more than once while they install, and for them Microsoft's advice is a count of 2 or more, or 0.
  3. Install the BIOS or firmware update and let the PC restart as often as it needs.
  4. A count of 0 keeps BitLocker suspended until you resume it yourself. If you used 0, resume as soon as the update has finished: Resume-BitLocker -MountPoint "C:" or manage-bde -protectors -enable C:.
  5. Check with manage-bde -status C: that Protection Status says Protection On. If not, resume it as in step 4 (or choose Resume protection in Manage BitLocker on Pro).

On Pro you can also choose Suspend protection in Manage BitLocker. Microsoft says protection then comes back when the PC restarts, so it suits an update that restarts only once.

While it's suspended, the key is stored unprotected on the drive. Microsoft says this “will allow anyone to access encrypted data”, so keep the PC with you and don't leave it suspended.

On Windows Home, Microsoft doesn't say whether these commands work (we've only tested them there without administrator rights). If one gives an error on Home, skip the suspend and keep your recovery key at hand for the update instead: if the recovery screen appears, type the key and Windows starts.

What can go wrong

  • manage-bde refuses to run. Run it in Terminal (Admin), as in the command-line steps above. If it still gives an error on Windows Home, use Settings.
  • Decryption doesn't seem to move. Check manage-bde -status. If it was paused, manage-bde -resume C: carries on. Keep the laptop on mains power.
  • A recovery screen appears at startup. Note the first 8 characters of the Key ID it shows and find the matching key at aka.ms/myrecoverykey. From Windows 11 version 24H2, the screen also shows a hint of which Microsoft account holds the key. Full help: find your BitLocker recovery key.

Stop it turning on during a fresh install

This is for people who build or reinstall PCs. Microsoft documents a registry value that prevents the automatic process:

  • Key: HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\BitLocker
  • Value: PreventDeviceEncryption, type REG_DWORD, data 1

PC makers can set the same thing in an unattended setup (answer) file. Microsoft's caveats come with it: keeping device encryption on is recommended; “we do not recommend setting this registry key on devices with Recall feature”; and its guidance for PC makers only allows them to disable device encryption when they ship their own encryption instead. The value prevents the automatic process; it isn't described as a way to decrypt. A drive that's already encrypted stays encrypted until you turn it off with the steps above.

The value stays in the registry after setup. Microsoft describes it as preventing the automatic process, so don't expect device encryption to switch itself on later on that PC, for example after Secure Boot is turned on. If System Information on that PC shows Disabled by policy under Device Encryption Support, this value is a likely reason (Microsoft doesn't document that message): see Disabled by policy.

What drive encryption doesn't cover, on or off

Device encryption and BitLocker protect a PC that's switched off. Once you're signed in, every file is readable to anyone using your account, and a copy you put on a USB stick, attach to an email or sync to OneDrive or Google Drive isn't covered at all. That's true whether you keep device encryption on or turn it off.

Questions

How do I turn off device encryption in Windows 11?

Save your recovery key first. Then sign in as an administrator, open Settings, Privacy & security, Device encryption, and set it to Off; this is the way Microsoft documents. Windows then decrypts the drive in the background. You can also run manage-bde -off C: in Terminal (Admin), which you open by right-clicking Start; afterwards, check that the Settings page shows Off.

Should I turn off device encryption in Windows 11?

For most people, no. Microsoft recommends keeping device encryption on for any PC that supports it: it stops someone reading the drive by taking it out of a lost or stolen laptop. The usual reasons to turn it off have better answers: save the recovery key against lockout, suspend it for a BIOS update, and check whether the slowdown is real on your PC.

Is it safe to turn off device encryption?

It's safe for your files: Windows decrypts the drive in place. What you lose is protection, because anyone who takes the drive out of a lost or stolen PC can then read it. Save your recovery key first, keep the PC plugged in, and let decryption finish.

Is Windows 11 encrypted by default?

On PCs that meet the requirements, yes: device encryption starts after setup, and Microsoft's Recall documentation says Device Encryption or BitLocker are enabled by default on Windows 11. It only protects the drive once the recovery key is backed up: on a personal PC, when an administrator signs in with a Microsoft account; on a work or school PC, when the organization backs the key up to Microsoft Entra ID or Active Directory. With only a local account, Microsoft says it isn't turned on automatically, though the drive may already be encrypted with an unprotected key.

Does turning off device encryption turn off BitLocker?

Yes. Device encryption is BitLocker switched on automatically, so turning it off decrypts the drive and removes BitLocker from it. Microsoft describes manage-bde -off, the command-line way to do it, as the command that decrypts the drive and turns off BitLocker. Afterwards, check every internal drive with manage-bde -status.

Does turning off device encryption delete my files?

No. It decrypts the drive in place and your files stay where they are. As before any long disk operation, back up anything you can't replace, and keep the recovery key until decryption has finished.

How long does it take to turn off device encryption?

Microsoft doesn't give a figure; it depends on the drive. Decryption runs in the background. Follow it with manage-bde -status in Terminal (Admin), where Percentage Encrypted counts down as the drive is decrypted. Keep a laptop plugged in until it finishes.

Does turning off device encryption improve performance or gaming?

Usually only a little. Microsoft says it has aimed to keep BitLocker's overhead within single-digit percentage points, but that the impact is more pronounced on fast NVMe drives, especially for I/O-heavy work like gaming or video editing. That's why it added hardware-accelerated BitLocker on some new processors. Whether the gain is worth an unprotected drive depends on what's on the PC.

Will device encryption turn itself back on?

Microsoft says that if device encryption is turned off in Settings, it will no longer automatically enable itself in the future; you'd turn it on again in Settings. It doesn't say the same for manage-bde or Manage BitLocker, so if you used those, check that the Settings page shows Off and run manage-bde -status again after the next feature update. A clean reinstall of Windows runs setup again, which prepares device encryption again on a PC that qualifies, and a work or school PC can be encrypted by policy.

I use a local account: is my drive encrypted?

It may be, without being protected. Microsoft says a PC that uses only local accounts remains unprotected even though the data is encrypted: the key is stored on the drive unprotected, and File Explorer shows a yellow warning icon on it. To protect it, sign in to Windows as an administrator with a Microsoft account, which backs up the key; otherwise, turning it off is the clean choice.

Why can't I turn off device encryption?

You need an administrator account; with a standard account, Microsoft says the Device encryption page may not appear at all. On a PC managed by a work or school, encryption might be required by policy, so ask IT. If the page is missing for another reason, see device encryption not available in Windows 11.

Do I need to turn off device encryption before a BIOS update?

No. Suspend it instead. Microsoft says suspending for planned firmware or hardware changes avoids the recovery screen and leaves the drive fully encrypted. In Terminal (Admin), run Suspend-BitLocker -MountPoint "C:" -RebootCount 2, install the update, and protection comes back by itself after two restarts. Then check that manage-bde -status C: says Protection On. If you suspend with a count of 0 instead, resume it yourself with Resume-BitLocker -MountPoint "C:" once the update is done. If Windows asks for the recovery key anyway, see how to find your BitLocker recovery key.
