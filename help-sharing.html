Share encrypted files without sharing a password

Sending a password-protected file means sending the password too. Clavis does it differently: everyone has a Clavis ID — a public key — and you encrypt files for someone's ID. Only their vault can open them. No password changes hands.

Having a Clavis ID, adding contacts and opening files shared with you are free. Encrypting files for someone is part of Clavis Premium.

Send with a password (free, for anyone)

For someone who doesn't use Clavis: right-click a file → Clavis → Send with a password… (or Send files with a password… in Sharing). It works on files you've already encrypted too. Clavis makes a locked copy named after the original (Tax return 2025.pdf.enc) and suggests a strong one-time password. Your original, or your own .enc, stays as it is.

  • Send the file any way you like, with the ready-made message: it tells them to open it at clavisenc.com/open.html, which works on a phone or any computer and uploads nothing.
  • Send the password a different way, such as a call or a text, not in the same email or chat as the file.
  • If they do use Clavis, they just double-click the file: Clavis notices it isn't locked with their vault password and asks for the file's own.

Your ID and your contacts

Choose Sharing in the sidebar.

Add a contact

Ask the person to send their ID (Copy my ID, or the .clavisid file). Then press Add from clipboard, Add from file…, or just double-click the .clavisid file.

Always compare the fingerprint with the person over a channel you trust — read it out on a call, or check it in person. That proves the ID really is theirs and not someone in the middle.

Encrypt files for someone

Right-click files in File Explorer → Clavis → Encrypt for someone… (or Encrypt files for… in Sharing), then pick one or more contacts.

Send the resulting .enc file any way you like — email, chat, a USB stick. Your contacts open it with Clavis (free), and Verify shows it really came from you: every shared file is signed.

Under the hood: each recipient gets the file key wrapped with X25519 + ML-KEM-768 (post-quantum hybrid), and the file is signed with Ed25519. See the Security page.
